<objective>
Prove the entire Phase 12 alerting architecture end-to-end with one production-quality vertical
slice: a single CAT I `verdict.ready` event travels bus → `q.alerting` → emitter → Store lookups
→ 7-field payload → authenticated HTTP POST to the ntfy `cnr-cat-i` topic. No dedupe, no throttle,
no digest, no retry/DLX, no `sab.published` trigger — those are expansion plans built out from this
proven slice.

Implements D-01 (standalone `apps/alerting` service, own container, own `/health` on a 22xxx port,
own durable `q.alerting` via the widened `ROUTING_KEY_TO_QUEUE` list mechanism) and the emission
half of T1-03 (ADR-015 D1 CAT I only, D2 ntfy single channel, D3 7-field payload).

Covers SPEC R1 (single-trigger half), R5 (obsidian:// deep link), R6 (fail-closed startup),
R8/P2 (excerpt cap, never sourced from the body column). Roadmap requirement: ADR-003 §Dissemination
(DI-5 "Push notifications on CAT I").

Purpose: retire the two genuinely unproven architectural risks in this phase (an outbound
authenticated HTTP egress from a new service, and the Obsidian note-path contract shared with
`apps/brief`) on the executor's best early-context tokens, before any expansion layer is committed.

Output: a running, containerized `apps/alerting` service that pushes real CAT I alerts.

## Assumption A-01 (surfaced, not silently resolved)

SPEC R5 states "`item_link`/`deep_link` are `obsidian://` URIs opening the item's vault note" —
two payload fields, one described target. Making them byte-identical would be a defect. This plan
resolves the ambiguity as:

- `deep_link` → the **item's** vault note (anchored in ADR-015 §Decision 3, which defines
  `deep_link` as the item note; this is the field SPEC R5's path-match acceptance criterion is
  checked against)
- `item_link` → the **SAB** note in the same vault (satisfies SPEC R8 "links back to vault/SAB";
  still an `obsidian://` URI, so R5's grammar requirement holds for both fields)

Rated `costly`, not `one-way` — reversing means changing one JSON string field plus an ADR line.
Surfaced to the operator for confirmation at the 12-09 human-verify checkpoint.
