  <action>
    Write `tests/test_alerting_prohibitions.py`. Every guard must be structural, never a raw-text
    grep of a source file — a comment in the file under inspection would otherwise be able to both
    trip and satisfy the check, which makes the guard worse than absent. Two helpers make this
    concrete and both must be used.

    `_published_ports(service_name)` loads `docker-compose.yml` with the YAML parser (which discards
    comments) and returns the service's published port strings. `_sql_string_constants(path)` parses
    a Python file with the standard-library AST module and returns every string constant that looks
    like SQL — one containing a select, insert, update, or delete keyword — so that only executable
    string literals are inspected and comments and docstrings are structurally out of scope.

    P1, the airgap guard (ADR-016 / T1-02): assert every published port of the ntfy service and of
    the alerting service begins with the loopback address prefix. Then assert, over the parsed
    service definitions, that neither service's environment mapping nor its command list contains any
    key or token naming an upstream server, a relay or forwarding target, an APNs or FCM
    configuration, or a hosted ntfy endpoint. Build that forbidden-token list inside the test from
    the parsed YAML values only. Apply the same loopback assertion to every other service in the file
    that publishes ports, so a future service cannot regress the doctrine silently.

    P2, the excerpt guard: three parts. First, drive the payload builder with an enrichment whose
    rationale is 5000 characters and assert the excerpt is at most 500. Second, walk every Python
    file under the alerting package, collect its SQL string constants with the AST helper, and assert
    none of them references the article full-text column as a selected or written identifier. Third —
    the strongest of the three — build one item with the full-text field populated and an otherwise
    identical item with it absent, run both through the payload builder, and assert the two payloads
    are equal. That equality is what actually proves the excerpt is not sourced from that column,
    independent of how any query is written.

    P3, the scorer guard: call the scorer's item-scoring function with the model call patched to
    capture the prompt, passing an item dict that carries an extra full-text key holding a distinctive
    sentinel string. Assert the captured prompt does not contain the sentinel, and does contain the
    title and the summary — so the test fails if the guard is bypassed AND if the prompt is gutted.
    Add a second case asserting the summary is still passed through the existing truncation the
    scorer applies, so the input contract has not widened.

    P4, the tier guard: re-assert at phase level what plan 12-04 asserts at unit level, because this
    is the prohibition most likely to regress when a future phase adds a tier. Drive the emit path
    with tier II, tier Routine, an absent tier key, and an explicit null tier, and assert zero
    requests reach the stub server in all four cases.

    P5, the no-independent-record guard: this is SPEC's one judgment-verified prohibition, so encode
    what can be encoded and leave the rest to the checkpoint. Parse `011-alert-state.sql` and assert
    its column set contains no column named for an excerpt, a summary, a rationale, or a full text —
    the table holds routing and bookkeeping plus the title needed for digest grouping, and nothing
    that would make it a second copy of the intel. Then assert the alerting worker registers no HTTP
    route other than the health endpoint, by inspecting the module for handler registrations rather
    than by starting a server.

    AC8, the failure-isolation proof: run the alerting emit path end to end with a store whose
    articles all have a NULL full-text field, and assert the alert still fires with a complete
    payload. Pair it with the P2c equality assertion so both directions are covered: body absent must
    work, and body present must change nothing.
