<objective>
Build the dedupe/throttle state substrate the alerting service runs on: the `infotriage.alert_state`
table and its Store-protocol methods, with PostgresStore and InMemoryStore parity.

Implements D-02 verbatim: a new Postgres table via migration `011-alert-state.sql`, accessed through
the existing Store protocol, 24h dedupe TTL expressed as an interval over `fired_at`, sliding windows
computed from `fired_at` timestamps, and no new infrastructure. The exact column set, index choice,
and sliding-window query shape are Claude's Discretion per D-02 and are pinned below.

Covers the storage half of SPEC R2 (dedupe with 24h TTL) and SPEC R3 (sliding-window throttle
bookkeeping). Roadmap requirement: ADR-003 §Dissemination.

Purpose: land the atomicity and clock-injection guarantees in one place so plans 12-04 and 12-05
consume a proven interface instead of re-deriving race semantics inside the emitter.

Output: a migration, five Store methods with dual implementations, and a parity test suite.

  <action>
    Declare six methods on the Store Protocol in `_protocol.py`, following the existing
    keyword-only-argument and docstring style, and implement each in both `_postgres.py` and
    `_inmemory.py` with matching signatures and matching semantics (D-02 parity, the same dual-impl
    shape put_enrichment/get_enrichment already follows).

    Every method that reasons about time takes a keyword-only `now: datetime | None = None`
    parameter defaulting to None meaning server time — this is what makes SPEC R2's injected-clock
    acceptance criterion and SPEC R3's sliding-window boundary test deterministic. In Postgres, bind
    it and coalesce: the timestamp expression is the bound parameter cast to timestamptz coalesced
    with `now()`. All values go through bind parameters; no f-string SQL anywhere (the security note
    at `_postgres.py`'s put_item docstring is the standing rule).

    `claim_alert(dedupe_id, item_id, cnr_tier, alert_id, *, ttl_seconds=86400, now=None) -> bool` —
    the atomic check-and-set. One statement: INSERT the row, ON CONFLICT on `dedupe_id` DO UPDATE
    setting fired_at and alert_id from the excluded row and resetting suppressed to false and
    digested_at, delivered_at, dlx_at to null, with a WHERE clause on the DO UPDATE that only fires
    when the existing row's fired_at is at or before the new timestamp minus the TTL interval
    (build the interval with `make_interval(secs => %s)` from the bound ttl_seconds), RETURNING
    dedupe_id. Return True when a row came back, False when none did. A fresh-within-TTL conflict
    returns no row, which is the suppress signal; a TTL-expired conflict updates and returns a row,
    which is the re-fire signal. Commit before returning. This single statement is the entire race
    window — there is no separate read.

    `count_alerts_in_window(*, window_seconds, now=None) -> int` — count rows where fired_at is
    strictly greater than the timestamp expression minus the window interval and suppressed is
    false. Roll back the read transaction before returning, matching the existing
    avoid-idle-in-transaction pattern.

    `mark_alert_suppressed(dedupe_id, *, pmesii=None, title=None) -> None` — set suppressed true and
    store pmesii and title on that row.

    `list_undigested_suppressed(*, now=None) -> list[dict]` — return dicts with dedupe_id, item_id,
    alert_id, pmesii, title, fired_at for rows where suppressed is true and digested_at is null,
    ordered by pmesii then fired_at ascending so the digest grouping is stable. Roll back after read.

    `mark_alerts_digested(dedupe_ids, *, now=None) -> None` — set digested_at on the listed rows in
    one statement using an ANY-of-array bind parameter; a no-op for an empty sequence.

    `mark_alert_outcome(dedupe_id, *, outcome, now=None) -> None` — accept the two string outcomes
    `delivered` and `dead_lettered`, setting delivered_at or dlx_at respectively; raise ValueError on
    any other outcome string (app-level validation, since the schema deliberately uses plain types).

    In `_inmemory.py`, back the same six methods with a dict keyed by dedupe_id holding the same
    field names, and replicate the TTL and window comparisons in Python against the injected now (or
    `datetime.now(timezone.utc)` when None) so the parity tests can assert identical returns. Use
    timezone-aware datetimes throughout — a naive/aware mismatch is the likeliest parity break.

    so the suite still runs green without a database. Include a concurrency assertion for Test 1/2:
