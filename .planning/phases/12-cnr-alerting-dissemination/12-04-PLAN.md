Expand the proven tracer slice to the dual-trigger, exactly-once shape SPEC R1 requires: bind
`sab.published` to `q.alerting` alongside `verdict.ready`, and gate every egress behind the atomic
dedupe claim landed in plan 12-02.

behavior end-to-end). Roadmap requirement: ADR-003 §Dissemination.

Purpose: the tracer proved the path; this proves the path fires exactly once no matter which trigger
arrives first, which is the single hardest correctness property in the phase.

Output: a dual-trigger emitter with no race window.

    `compute_dedupe_id(item_id, cnr_tier)` returns the sha256 hex digest of the item id joined to the
    tier by a pipe character, truncated to the first 16 characters — the formula locked in SPEC R2.
    Note this supersedes the at-sign separator in the older ADR-015 §Decision 3 table; ADR-015 is
    amended in plan 12-09. Add a module docstring recording that the 16-character truncation is

    id and delegates to the Store's `claim_alert`, returning a tuple of the dedupe id and the boolean
    claim result. It performs no read before the write — the single INSERT-ON-CONFLICT statement in
    the Store is the entire race window (SPEC R1 "atomic check-and-set, no race window"). Do not add
    an in-process set, lock, or cache in front of it: an in-process guard is invisible across a
    restart and across the two trigger paths, which is precisely the failure mode this design avoids.

    Refactor `apps/alerting/emitter.py`'s `build_alert_payload` to import and call
    `compute_dedupe_id` rather than inlining the hash, so there is exactly one definition of the
    identity in the tree.

    injected clock rather than sleeping.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| RabbitMQ → emitter handler | Two distinct message shapes arrive on one queue; a shape confusion is an input-validation failure |
| concurrent trigger delivery → alert_state | The two triggers can be in flight simultaneously for the same item |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-15 | Denial of Service | duplicate pushes from dual triggers | high | mitigate | Atomic claim before any egress; both trigger orders asserted to produce exactly one request (SPEC R1) |
| T-12-16 | Tampering | shape confusion between the two events on one queue | medium | mitigate | Dispatch on the decoded event discriminator field, not on the delivering consumer; the sab branch never reads an article id from the header |
| T-12-17 | Denial of Service | alert flood via repeated re-scoring of one item | high | mitigate | 24h TTL on the claim suppresses re-alerts for the same tier; volume across distinct items is handled by plan 12-05's throttle |
| T-12-18 | Spoofing | a non-CAT-I verdict reaching the CAT I topic | high | mitigate | Tier gate before the claim on both branches; asserted for cnr II, Routine, absent, and null (prohibition P4) |
| T-12-SC | Tampering | pip installs | high | accept | No package installs in this plan |
</threat_model>
