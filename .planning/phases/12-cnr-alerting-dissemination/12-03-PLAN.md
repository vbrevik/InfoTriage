<objective>
Top off shipped sub-wave (a): provision the ntfy bearer token SPEC R6 requires and tighten the topic
ACL from a single wildcard grant to the explicit per-topic grants SPEC R6 specifies.

This is the one genuinely unsolved piece of engineering in the phase. The shipped `apps/ntfy/Dockerfile`
(ADR-018) pre-bakes Basic Auth users only; `ntfy token add` mints a server-generated value that
cannot be chosen ahead of time and therefore cannot ride the existing BuildKit-secret pre-bake path
(RESEARCH Pitfall 2, Open Question 1). The token is generated post-boot and captured by the operator
into the gitignored `.env` — never into an image layer.

Also produces the phase COVERAGE.md ntfy capability matrix, recording which parts of the ntfy
publish surface this phase integrates and which it deliberately opts out of.

Covers SPEC R6 (ACL half — the fail-closed emitter half ships in 12-01) and prohibition P1's ground
truth. Roadmap requirement: ADR-003 §Dissemination.

Output: a tightened ACL, an idempotent `make ntfy-token` target, an updated ADR-018, a live ACL test,
and COVERAGE.md.

    In `apps/ntfy/Dockerfile`'s builder-stage RUN block, replace the two wildcard grants — currently
    a write-only grant to the producer identity on the topic prefix followed by a star, and a
    read-only grant to the reader identity on the same pattern — with explicit per-topic grants, so
    that topic-vs-wildcard precedence is never relied on. Keep the topic prefix arriving from the
    existing BuildKit secret; derive the three topic names from it as the prefix itself, the prefix
    with a `-debug` suffix, and the prefix with a `-test` suffix.

    Grants required by SPEC R6:
    producer identity gets `read-write` on the primary topic (the emitter's bearer token is minted
    for this identity and inherits the grant; SPEC R6 requires the primary topic to require a token
    for read AND write);
    producer identity gets `write-only` on the debug topic and on the test topic;
    reader identity gets `read-only` on the primary topic and no grant at all on the debug or test
    topics (SPEC R6: "reads gated to operator UID" — the reader identity is not the operator UID).

    Leave `NTFY_AUTH_DEFAULT_ACCESS=deny-all` and the serve-then-kill auth.db bootstrap untouched;
    they are load-bearing and already shipped. Do not add a `ntfy token add` call here — a token
    minted at build time would land in an image layer, which is exactly what ADR-018's philosophy
    forbids and what Task 2's post-boot flow exists to avoid.

    Update the file-header comment to state the three-topic grant matrix and why explicit grants
    replaced the wildcard.

    Create `.planning/phases/12-cnr-alerting-dissemination/COVERAGE.md` as the ntfy capability matrix
    for this phase. One row per capability, each marked INTEGRATE or OPT-OUT with a one-line reason:

    click-action (INTEGRATE — the click header carries the obsidian deep link, SPEC R5);
    attachment (OPT-OUT — the SAB is the canonical record, an attachment would make the push an

    delayed delivery (OPT-OUT — CAT I alerts are immediate by definition; volume is handled by the

  <action>
    Add two targets to `ops/Makefile`, registering both in the `.PHONY` list and giving each a
    double-hash help comment matching the existing style.

    `ntfy-token` — mint or reveal the emitter's bearer token, idempotently. It runs against the
    already-running container by name. First it lists existing tokens for the producer identity; if
    one already exists it prints that token and a note that no new token was minted, and exits 0.
    Only when none exists does it call the token-add subcommand for the producer identity. Either way
    it finishes by printing an instruction block telling the operator to copy the printed value into
    the gitignored `.env` as the token key, and stating that the alerting service refuses to start
    while that key is empty. The target must never write the token into any tracked file, must never
    echo it into a build argument, and must not attempt to edit `.env` itself.

    `ntfy-acl-check` — a fast operator-facing smoke that exercises the SPEC R6 matrix with curl
    against the published localhost port: an unauthenticated POST to the primary topic must return
    403, an authenticated POST with the bearer token from `.env` must return 200, and an
    unauthenticated GET of the primary topic's json stream must return 403. Print a one-line PASS or
    FAIL per case and exit non-zero if any case fails.

    Amend `docs/adr/ADR-018-ntfy-dockerfile-prebake.md` with a section titled
    `## Amendment — bearer token provisioning (Phase 12)` recording: that SPEC R6 requires a bearer
    token, not Basic Auth; that ntfy generates the token value rather than accepting a chosen one, so
    the BuildKit-secret pre-bake path used for passwords does not apply; that the token is therefore
    minted post-boot via the make target and captured only into the gitignored env file, which
    extends rather than contradicts ADR-018's "only bcrypt hashes land in image layers" philosophy
    (a token is bearer-equivalent and is used directly, so it is strictly higher-value than a hash);
    and that the wildcard topic grant was replaced by explicit per-topic grants, listing the matrix.

    Write `tests/test_alerting_auth.py` covering the same matrix in pytest form, skipped by default
    when the ntfy port is not reachable, using the same reachability-probe convention
    `tests/conftest.py` uses for the database marker. Cases: unauthenticated publish to the primary
    topic returns 403; publish with a deliberately wrong bearer token returns 401 or 403; publish
    with the real token from the environment returns 200; unauthenticated read of the primary topic
    returns 403. Read the token from the environment only — the test must fail with a clear skip
    message rather than embedding any credential.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| any local process → ntfy HTTP | Anything on the host loopback can attempt to publish to the topic |
| operator .env → container env | The bearer token crosses from the gitignored file into the running container |
| image build → image layer | Anything written in the builder stage is recoverable from docker history |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-10 | Spoofing | ntfy cnr-cat-i topic | high | mitigate | deny-all default plus explicit per-topic grants; unauthenticated publish returns 403, asserted by both the make target and tests/test_alerting_auth.py |
| T-12-11 | Information Disclosure | apps/ntfy/Dockerfile image layers | high | mitigate | No token-add call in any build stage; the token is minted post-boot and captured only into the gitignored .env — asserted by a zero-count grep criterion in Task 1 |
| T-12-12 | Information Disclosure | ops/Makefile ntfy-token output | medium | mitigate | The target prints the value to the operator's terminal only; it writes no file and passes the value to no build argument. Recorded in the ADR-018 amendment |
| T-12-13 | Elevation of Privilege | reader identity gaining debug/test topic reads | medium | mitigate | Explicit per-topic grants replace the wildcard, so the reader identity has no grant on the debug or test topics rather than an inherited one |
| T-12-14 | Information Disclosure | ntfy relaying off-host | high | mitigate | Base URL and port binding stay loopback-only; no upstream or forwarding configuration is introduced (ADR-016, prohibition P1 — mechanically asserted phase-wide in plan 12-09) |
| T-12-SC | Tampering | pip/apt installs | high | accept | No package installs in this plan; the ntfy base image tag is unchanged from the shipped ADR-018 state |
