<objective>
Close the second half of the bundled Phase 13 sub-wave (f) that T1-01's INTEGRATED-SUB-WAVE workflow
shape brings into this phase: populate `articles.body` from all seven ingest adapters.

Implements the adapter half of D-04. Each adapter sets the one new field on its existing `Item`
construction where the source carries full text, and leaves it unset where the source does not. No
adapter changes its `persist_and_publish` call site — the field rides the existing choke point.

Covers the adapter half of SPEC R7 and its per-adapter acceptance criterion. Roadmap requirement:
ADR-003.

Purpose: this is the producer-side gap `libs/store/sql/009-articles-body.sql`'s own migration comment
names. The column and the brief-side reader already exist; nothing writes it. After this plan,
downstream phases may assert body population — which is exactly what T1-01 anchors in HANDOFF.json.

Output: seven one-field adapter changes and three grouped test files covering all seven.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| remote source → adapter → Item.body | Full untrusted remote content, including attacker-controlled HTML and arbitrary-length transcripts, enters the system by design |
| adapter → persist_and_publish → Postgres | The unbounded value reaches storage through the shared choke point |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-34 | Tampering | untrusted remote content stored unsanitized | medium | transfer | Sanitization belongs to the rendering surface, not the ingest write path — the brief link-view renderer, already flagged in 009-articles-body.sql's own comment. This plan adds no rendering surface, and the alerting path never reads the column (plan 12-09's P2 test) |
| T-12-35 | Denial of Service | an oversized transcript exhausting memory or storage | medium | accept | SPEC R7 locks no size cap; the ≥1MB fixture in Task 2 proves the behavior is intentional. Adapters already hold the full text in memory before construction, so this plan adds no new peak |
| T-12-36 | Tampering | body content reaching the scorer prompt | high | mitigate | No adapter changes any summary derivation, and the scorer reads the title plus the truncated summary only. Asserted per-fixture here and phase-wide by plan 12-09's P3 test |
| T-12-37 | Information Disclosure | email body content persisted for the first time | low | accept | The operator's own mailboxes, already ingested with subject and snippet, on a single-user local deployment (ADR-016). Existing vault-inclusion controls govern what reaches the vault |
| T-12-SC | Tampering | pip installs | high | accept | No package installs — every adapter change is a single keyword argument on an existing constructor call |
</threat_model>
